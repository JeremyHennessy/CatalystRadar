# SEC observation timing boundary

The discovery archive records what this run retrieved, not what a historical
trader could have known. SEC acceptance time, filing date, metadata retrieval,
and complete-document retrieval are different clocks.

Each event now retains the source URL, archive path, hash and retrieval timestamp
of every identical returned metadata row. `discovered_utc` is the earliest such
retrieval in this run. Historical-file rows must not borrow the earlier recent
submissions response time. `document_observed_utc` is populated only after the
existing limited document-response checks pass; this is not factual extraction
verification. `first_public_utc` remains null and eligibility remains blocked.
Explicit timezones are required rather than silently using the machine timezone.

Conflicting duplicate accessions fail closed; identical duplicates preserve both
source vintages. A record absent from current results does not prove deletion or
historical absence. This does not add a cross-run revision/deletion ledger or
reconstruct dissemination times. Existing archives are not rewritten or backdated.

The [SEC data access guidance](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)
describes late dissemination and index updates, including later corrections.
Current indexes and filing dates therefore cannot alone establish point-in-time
availability. Index reconciliation remains a current-snapshot comparison, not
proof of historical availability. A future historical study needs archived
source vintages and a separately validated availability policy.

Six synthetic regression cases cover historical response timing, duplicate
vintages, conflicting revisions, invalid documents, missing records and naive
timestamps. No provider requests or historical trading results are generated by
these tests. No live collection schedule or paper-book activation changes.
