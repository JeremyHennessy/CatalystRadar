# Bounded insider field-conflict source review

The offline builder reuses the existing full-field transaction diagnostic audit on the retained Q2 insider database and archive. Both input hashes are pinned to the independently retained Q2 lineage and verified before/after processing. No network request, new collection universe, owner join, value aggregation or execution operation occurs.

Result: 78,328 nonderivative source rows audited; **65 rows in 45 filings across 34 issuer CIKs** contain opposing P/S and acquisition/disposition fields (P:D or S:A). Of those rows, 33 have footnote context, three are amendments and six have deemed-execution-date context. Diagnostics overlap. These are unresolved reported field combinations, **not findings of erroneous filings, market trades, misconduct or economic direction**.

`web/insider-conflict-review.json` is a bounded source-review queue, not yet integrated into an app view. Each card groups an accession, preserves counts by reported code pair, source-row hashes and transaction keys, flags additional context, and states missing requirements. The SEC search link is a navigation aid, not verification of the original filing. The actual retained source is the linked prepared archive. There are no names, owner information, quantities, prices, currency, monetary totals or footnote narratives in this public projection.

The Q2 filing quarter is not the transaction quarter. Generation time is the current audit clock, not historical availability. Amendments remain separate; Form 4/A may amend selected lines without repeating unchanged lines. Do not assume whole-filing replacement. The queue has no forecast, profitability, training or trading admission status. The explicit empty queue means no qualifying conflict in the audited inputs, not absence of insider activity. A different source archive/database requires re-audit rather than silent substitution.

Implementation: `backend/insider_conflict_queue.py`. The reusable `build(database,database_sha256,archive,archive_sha256)` function returns the projection after complete existing source audit; `project(records)` accepts validated audit rows for deterministic selection. Output is bounded to 100 filings. It rejects inconsistent diagnostics, duplicate row identities, invalid issuer/accession, wrong filing periods, missing hashes and conflicting submission metadata. This package does not change the existing watchlist-specific insider desk or public/private boundary.
